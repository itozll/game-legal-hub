BlockPop Privacy Policy

Status: Draft for publication (not yet effective)
Version: 1.0.0-draft
Updated: 2026-10-28
Effective date: To be confirmed before publication

1. Scope and operator

This draft describes information handling by the current BlockPop classic game and its privacy pages. The operator's legal identity, privacy contact email and intended release regions have not been supplied and must be confirmed before publication. A repository account name is not treated as the operator's identity. This is not an effective policy.

The game may run in a browser or host application. The host controls its own accounts, permissions and processing; its privacy policy also applies to those activities. The four language versions should remain consistent, and translation differences do not restrict rights under applicable law.

2. Information used and purposes

To resume unfinished games and retain scores and sound choices, the game saves board cells, available pieces, score, combo and non-clearing move counts, tile colors, the best score and the sound setting in local storage provided by its runtime. These records support gameplay and preferences, not advertising profiles.

The game reads the application language supplied by its host to choose Chinese, English, Russian or Arabic. It falls back to English if the language is unsupported or the interface is unavailable. The current implementation does not save language preferences or substitute the device language.

The current game has no registration, sign-in, cloud saves, payments, advertising SDK, independent behavioral analytics or crash reporting. It does not actively collect names, phone numbers, contacts, precise location, identity documents, photographs, camera or microphone data. There is no feature uploading game saves to a developer server. Local piece generation and scoring do not identify players.

3. Retention, deletion and security

Saves and preferences remain on the device or in local storage supplied by its runtime, usually until the player clears the relevant site or host game data, or the runtime removes it. Uninstall, backup and restore behavior depends on the platform. The game promises neither cloud recovery nor that a host never backs up local data.

Players can change sound settings and remove local records using browser site-data controls or a host's game-data removal feature. Deletion may permanently remove the current game and best score. The operator cannot remotely access or delete saves that exist only locally and have not been supplied to it. Local storage is not anonymization or encryption; people with device or host-storage access may see these records.

The operator should apply safeguards appropriate to its actual processing and confirm retention, processing grounds and rights procedures before publication. No system can be promised absolute security.

4. Hosts, network requests and policy pages

Loading the game, audio, images or policy pages sends the network requests needed to deliver that content to its actual hosting service. Optional remote computation-module downloading is currently disabled; enabling it requires checking its source and logging. Resource downloading is not uploading game saves. Hosts and hosting providers may independently process account, device or network information. Their actual categories, purposes, retention, locations and international processing must be verified before release; third-party data is not promised to stay local.

These four policy reading pages are static, contain no advertising, analytics scripts, tracking pixels or external fonts, and do not read game saves. If hosted on GitHub Pages, GitHub logs and stores visitor IP addresses for security. See GitHub Pages data collection and the GitHub Privacy Statement.

5. Requests, minors and future features

The published policy must provide a working privacy contact. Players may request access, correction, deletion or other rights available under applicable law and contact hosts about their independent processing. Specific rights and processing grounds must be confirmed for the actual release regions. If players contact the operator, it should use the contact details and issue content only as needed for the request and as permitted by law, without requesting unrelated identity documents or complete saves.

Minors should follow local and host age requirements with guardian guidance where needed. The current implementation has no age collection or identity verification; this does not establish that every region's child-protection procedures are complete. Required guardian-consent procedures must precede the relevant processing; starting the game is not that consent.

Before adding advertising, accounts, payments, cloud saves or analytics, update this policy, verify recipients and processing, and provide notices and consent arrangements required by applicable law.

6. Updates and publication

Material changes to features or processing require consistent updates to the version, date and four language texts, with notice where required. Before the policy becomes effective, confirm the operator, contact, release regions, actual hosts and hosting services, retention and deletion arrangements, and the real effective date. See the publication checklist.
